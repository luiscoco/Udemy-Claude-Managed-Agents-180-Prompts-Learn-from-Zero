# Lesson applications and recordings

- Use the approved Prompt 1 course style for subsequent lesson apps. Follow the C01/C32 reference series with navy/orange headings, blue controls, rounded pastel panels, astronaut artwork, readable text, light/dark themes and presentation mode.
- Every code snippet shown in a lesson application, screenshot or video must use coloured syntax highlighting and readable monospace formatting. This is a standing user preference for the current lesson and subsequent lessons.
- Label each snippet with its actual language and select the corresponding grammar, such as TypeScript, JavaScript, JSON, YAML or shell.
- Preserve source text, indentation and punctuation when applying highlighting. Encode source text safely before inserting highlighted markup.
- Serve highlighting assets locally so recordings work without a CDN connection. Prompt 1 uses Prism with a pinned dependency and a high-contrast palette on navy code panels.
- Verify highlighting after dynamic content updates and in both light and dark themes. Recording walkthroughs must show the highlighted code and allow time to read it before continuing.
- Narrated course videos use Inworld voiceId `Yash`, modelId `inworld-tts-2`, enhanceGeneration `true`, deliveryMode `BALANCED`, and audioConfig `{ speakingRate: 1.25, audioEncoding: "MP3", sampleRateHertz: 48000 }`. Omit the language field for automatic detection. Read credentials from the process environment; never embed them in lesson assets or source.
- Follow the supplied SDK course-labs video's visual style and content structure for narrated exports. Set each cover to its actual new prompt title and vary its background palette and astronaut pose to match the topic. Retain coloured code, real application demonstrations, captions, chapter markers and the reference cube transitions.
- Red focus rectangles must follow the narrated detail using word timestamps, including the cover and opening concept slide. Frame a specific control, sentence, code line, diagram detail or table cell. Remove the rectangle when that detail is no longer being discussed. Do not frame whole screens or broad panels, cross unrelated text, clip boxes to the viewport or leave stale highlights on screen. Assign highlights to explicit video timestamps and check actual encoded frames at every cue, including gaps and control movement. Do not infer annotation timing from screencast duration.
- Prefer the smallest meaningful focus area: the code expression being explained, the relevant sentence inside an editor, or the diagram symbol itself. Include attached punctuation and leave space around glyphs so a border does not cross neighboring characters. Avoid stretching a code highlight across empty space or outlining an entire text field when only one sentence is relevant.
- On cover slides, include red rectangles only around the lesson title and the author name. Do not highlight cover illustrations, icons, the astronaut or the portrait.
