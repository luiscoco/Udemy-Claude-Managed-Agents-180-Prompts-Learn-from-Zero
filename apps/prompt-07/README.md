# Prompt 7 · Declarative Configuration

Runnable lesson for “Manage agent and environment definitions with ant apply and claude-lock.json; demonstrate a repeatable update.”

The app uses the approved navy/orange course design, astronaut artwork, light/dark themes and presentation mode. Markdown with YAML frontmatter, environment YAML, JSON and TypeScript are syntax highlighted with local Prism assets. PowerShell examples are highlighted as well.

## Run the application

Use Node.js 24+. In PowerShell, run the following commands.

```powershell
cd apps/prompt-07
npm ci --workspaces=false
npm start
```

Open http://127.0.0.1:4070. Use http://127.0.0.1:4070/?presentation=1 for recording.

## Classroom exercise

The browser runs an educational local reconciler with synthetic resources. Its snapshot is saved in `.runtime/classroom.json`, including applied definitions, mappings, inventory and history. The simulation uses SHA-256 fingerprints. The real ant CLI generates and interprets its own lockfile hashes.

1. Review the initial plan and apply it. The classroom inventory gains an agent and environment, with their IDs recorded in the displayed lockfile.
2. Select **Use revised instructions**, review the update and apply it. Inspect the unchanged agent ID and agent version 2.
3. Review and apply again. Both definitions are unchanged, and the agent version stays at 2.
4. Enable **Simulate a missing lockfile** and review. The proposed creates illustrate the loss of file-to-ID mappings. Existing local resources remain in the inventory if this simulated plan is applied.
5. Try the renamed agent path. The local plan creates a resource for the new path and retains the previous mapping.

Select a plan row to inspect its before/after JSON. Download the current definition or classroom lockfile for review. Reloading restores the last applied definitions and history. Unapplied form edits remain browser drafts.

This lesson supports a small definition subset: agent name/model with Markdown system instructions, plus cloud environment name and networking type. The model is recorded locally. Availability in your actual account is checked by the real service during your account workflow.

The classroom snapshot commits locally as one file. A stale or already-applied plan token is rejected. Its resource checks also detect differences from the last recorded remote configuration. The real CLI has its own reconciliation and failure handling.

## Use the real ant CLI

Install and authenticate the official ant CLI using its [quickstart](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart). The example project under `definitions/` contains `agents/reviewer.md` and `environments/reviewer.yaml`. Choose a model available to your account, then run these commands from the lesson folder.

```powershell
Set-Location definitions
ant auth login
ant apply --dry-run .
ant apply .
# Edit agents/reviewer.md, then review and apply again.
ant apply --dry-run .
ant apply .
Get-Content claude-lock.json
```

Agent frontmatter supplies configuration and its Markdown body supplies system instructions. The environment file supplies cloud sandbox configuration. The CLI records file paths and resource IDs in `claude-lock.json`. Keep that file with the definitions in version control. Compare the same agent ID and updated version after editing. The local classroom download uses a demo origin and IDs. Your account workflow uses the lockfile generated by ant in `definitions/`.

The CLI plan can be reviewed before applying. A renamed definition path represents a new resource. A partial account apply may still record created resources, so retain the updated lockfile after failures. Run account applies serially. See the official reference for workspace matching, drift handling and additional flags.

The ant executable was unavailable in this session. The account commands are provided for your authenticated terminal workflow. Classroom verification covers the application’s local model.

## Verify and record

```powershell
npm run check
npm test
npm run test:e2e
npm run record
```

Core checks exercise stable IDs, single-version updates, unchanged repeats, formatting-independent comparisons, file renames, missing lock mappings, stale/concurrent plans, simulated remote drift and failed local persistence. Browser checks cover the workflow, downloads, restoration, source fidelity, highlighting in both themes and mobile layout.

Playwright owns port 4070 during tests and stops its server afterward. Close an existing lesson server first. It uses installed Chrome on Windows or Playwright Chromium elsewhere. Set PLAYWRIGHT_CHROMIUM_EXECUTABLE to override it. Browser tests use `.runtime/playwright/classroom.json`.

The recording is a 1920×1080 WebM, with a review copy at `artifacts/prompt-07-demo.webm`. Screenshots are saved alongside it for later MP4 lesson production.
